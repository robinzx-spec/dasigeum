1. 운영자와 방침의 범위

다시금 서비스 운영자는 회원가입·로그인, 포인트 적립, 제휴 쇼핑, 출금 및 문의 처리를 위해 필요한 개인정보를 처리합니다. 이 문서는 현재 앱·서버 코드에서 확인한 처리와 운영자가 추가 확인해야 할 사항을 구분한 개인정보처리방침 초안입니다.

[운영자 확인 필요 · U01] 개인정보처리자 상호 또는 성명·주소·대표자 등 운영자 정보를 확정해야 합니다.

이메일 가입에 이름·전화번호·생년월일·성별·주소·닉네임을 필수 항목으로 추가하지 않습니다. 출금계좌 정보는 출금 기능 이용 시 처리합니다. 개인정보처리방침의 확인은 법적으로 필요한 별도 동의를 대신하지 않습니다.

2. 처리 목적과 항목

이메일 계정 및 인증

목적
계정 생성·로그인·세션 유지·계정 구분
항목
이메일, 비밀번호 인증 정보, Supabase 사용자 UUID, 로그인 제공자 연계 정보, 인증 세션·토큰 및 인증 흐름 정보
처리 경로
이메일·비밀번호는 공식 Supabase Auth SDK를 통해 인증 서버로 전송합니다. 다시금 앱은 비밀번호 원문을 별도의 앱 저장소나 업무 테이블에 저장하는 구현을 두지 않습니다. Supabase Auth는 비밀번호 해시를 저장하는 구조입니다. 인증 세션은 앱의 로컬 저장소에 유지됩니다.
법적 근거·보유기간
[운영자 확인 필요 · U17·U18] 목적별 근거와 기산점·기간을 확정해야 합니다.

현재 이메일 확인 없이 가입하며, 비밀번호 찾기는 비활성화되어 있습니다. 이 설정을 이메일 소유권 확인 완료나 본인 실명 확인으로 설명하지 않습니다.

Kakao 로그인

목적
소셜 인증과 계정 구분
항목
제공자 계정 연계 식별정보·인증 세션. 현재 요청 scope는 닉네임과 프로필 이미지입니다.
처리 경로
Kakao 인증과 Supabase Auth를 통해 처리합니다.
법적 근거·보유기간
[운영자 확인 필요 · U17·U18] 목적별 근거와 기산점·기간을 확정해야 합니다.

[운영자 확인 필요 · U19] 닉네임·프로필 이미지가 실제 Auth 메타데이터·identity 등에 저장되는지, 제공자 토큰의 저장 범위와 기간을 비밀값 없이 확인해 정확한 항목으로 확정해야 합니다. 요청 scope만으로 별도 프로필 DB 저장을 단정하지 않습니다.

Naver 로그인

목적
소셜 인증과 계정 구분, 인증 흐름 재사용 방지
항목
Naver 회원 식별자, 연계된 Supabase UUID·identity와 인증 세션, OAuth 흐름 식별·code의 해시 및 생성·만료·소비 상태 기록
처리 경로
adapter는 Naver 사용자정보 응답에서 식별자만 sub로 전달하며 이메일·이름·닉네임·프로필 이미지를 전달하지 않습니다. 인증 과정에서는 일시적으로 Naver 접근 토큰을 처리하고 암호화된 제한용 handle을 사용합니다. 토큰 원문을 일반 회원정보로 저장한다고 표현하지 않습니다.
법적 근거·보유기간
[운영자 확인 필요 · U17·U18] 목적별 근거와 기산점·기간을 확정해야 합니다.

거래 상태 코드에는 만료 후 추가 시간이 지난 행을 요청 시 정리하는 조건이 있습니다. 이는 모든 로그·백업까지 같은 시간에 파기됨을 의미하지 않습니다.

[운영자 확인 필요 · U20] 실제 identity 저장 범위, 인증 흐름 기록·handle·제공자 토큰과 로그의 보존·정리 동작 및 실행 주기를 확인해야 합니다.

제휴 쇼핑·적립·정산

목적
구매 실적과 회원 매칭, 예정·확정·취소 처리, 조정·이의신청
항목
회원 연계 식별정보(affiliate_user_id와 reward_uid 매칭), 가맹점·제휴 식별자, 실적 일자·시각, 주문코드, 상품코드·상품명·분류코드·수량, 구매금액·수수료 및 관련 구분값, 실적 식별자(trlog_id·uniq_id), 적립·취소·정산·조정 상태와 기록
처리 경로
앱의 쇼핑 이동 요청 본문에는 merchant_id가 포함됩니다. 인증된 요청이 affiliate-go 서버를 거쳐 이동 URL을 받습니다. LinkPrice 실적 수신 처리 코드에서 위 거래 필드를 검증·서버에 전달합니다.
법적 근거·보유기간

[운영자 확인 필요 · U21] affiliate-go 서버 구현은 앱 저장소에 없습니다. LinkPrice로 보내는 정확한 회원 식별자·URL 매개변수, 쿠키·조회 API 요청 및 실제 활성 수신·보존 필드를 운영 소스와 계약으로 확인해야 합니다. 수신 스키마는 매 요청에서 모든 선택 항목이 존재한다는 의미가 아닙니다.

3. 처리 근거 및 최소 수집

각 목적에 필요한 항목만 처리하고 목적이 달라지는 경우 적법한 근거를 확인합니다. 필수·선택 항목과 동의 거부의 영향을 구분해야 합니다. 출금 정보는 출금을 이용하지 않는 회원에게 가입 조건으로 요구하지 않습니다.

[운영자 확인 필요 · U17] 각 처리별 개인정보 보호법 제15조 등 적용 근거를 검토하고, 동의를 받아 처리하는 항목과 계약 이행 등 동의 없이 처리하는 항목을 구분해야 합니다. 필요한 동의가 있다면 목적·항목·기간·거부권과 불이익을 별도로 고지해야 합니다. 현재 가입의 “개인정보 처리방침 동의” 체크만으로 모든 처리가 적법해졌다고 보지 않습니다.

[운영자 확인 필요 · U03] 아동·미성년자 정책과 필요한 법정대리인 동의·권리행사 절차를 정해야 합니다.

4. 처리 및 보유기간

처리 목적이 달성되어 더 이상 필요하지 않은 개인정보는 관계 법령에 따라 파기합니다. 법령에 따른 보존이 필요한 경우에는 해당 근거·항목·기간을 구분하고 목적을 제한해 보존합니다. 모든 기록을 “탈퇴 시까지” 또는 “영구 보관”으로 일괄 처리하지 않습니다.

[운영자 확인 필요 · U18] 계정·인증/identity, 출석·설문 응답, 쇼핑 실적·장부·조정, 계좌 원문·지급 스냅샷·출금, 탈퇴·문의, 로그·백업 각각의 기간·기산점·법적 근거·분리 보존 방법을 확정해야 합니다. 전자상거래 등 관련 법령의 적용 여부도 검토해야 하며, 예시 보존기간을 서비스 전체에 일괄 적용하지 않습니다.

5. 파기 절차 및 방법

운영자는 파기 대상과 법적 보존 대상을 구분하고, 불필요한 개인정보는 복구되지 않도록 삭제하거나 매체에 적합한 방법으로 파기합니다. 종이 자료를 사용하는 경우에는 파쇄 등 적절한 방법을 적용합니다. 법적 보존 기록은 일반 서비스 이용 목적과 분리해 관리합니다.

현재 탈퇴 요청은 운영자의 검토를 거치며 자동 삭제 완료를 뜻하지 않습니다. 진행 중 거래가 있다는 이유만으로 관계없는 모든 개인정보의 파기를 무기한 미루지 않습니다.

[운영자 확인 필요 · U12·U18] Auth 계정·identity, 관련 데이터·Vault 참조·지급 스냅샷, 로그·백업의 실제 삭제 또는 분리 보존 절차와 처리기한을 확인해야 합니다. 코드의 삭제 방지 장부 설계가 법적 영구 보존 근거는 아닙니다.

6. 제3자 제공

외부 서비스와 통신한다는 사실만으로 제3자 제공 또는 위탁 관계가 확정되는 것은 아닙니다. 제3자 제공에 해당하는 처리가 있으면 적법한 근거를 확인하고 제공받는 자·목적·항목·보유기간 및 필요한 동의 내용을 공개해야 합니다.

[운영자 확인 필요 · U23] Kakao·Naver·LinkPrice·제휴 쇼핑몰·송금 은행 등과의 계약 및 실제 데이터 흐름을 기준으로 제공 여부와 법적 역할을 확정해야 합니다. 현재 “제3자 제공 없음” 또는 특정 업체에 포괄 제공한다고 확정하지 않습니다.

7. 개인정보 처리업무 위탁

Supabase Auth·데이터 저장 및 서버 기능의 이용은 코드에서 확인됩니다. 다만 이 사실만으로 계약상 수탁자 명칭, 업무 범위, 재위탁과 법적 역할을 확정하지 않습니다.

[운영자 확인 필요 · U24] 실제 계약 상대방의 법인명, 위탁 업무·처리 항목, 재위탁 업체, 감독·안전조치, LinkPrice·은행 업무의 위탁 여부를 계약으로 확인해 공개해야 합니다. GitHub Pages 호스팅과 관련 처리도 확인 대상입니다.
